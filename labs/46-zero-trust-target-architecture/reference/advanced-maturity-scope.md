
# Advanced Maturity Scope

`ADVANCED_TARGET` is a planning state. `ADVANCED_VALIDATED` requires capability-specific evidence and a source maturity-table reference. Architecture, product presence, a running container, or one health check cannot establish it.

| Selection | Count | Meaning |
|---|---|---|
| ADVANCED_PRIMARY_TARGET | 21 | Golden Path control with credible bounded runtime and IaC/CaC/PaC operation |
| ADVANCED_SUPPORTING_TARGET | 15 | Supporting control with narrower subjects, resources, or evidence breadth |
| INITIAL_TARGET | 4 | Bounded implementation target while Advanced conditions remain unmet |
| DESIGN_ONLY | 5 | Traceability and interface design without implementation inference |
| OPTIMAL_ROADMAP_ONLY | 7 | Future dynamic, behavioral, or closed-loop function |

## Assessment Boundary

- Official levels: `TRADITIONAL`, `INITIAL`, `ADVANCED`, `OPTIMAL`.
- Repository-only states: `UNASSESSED`, `NOT_APPLICABLE`.
- Current maturity remains capability-specific and `UNASSESSED` for all 52 capabilities.
- No overall repository score is assigned.
- `OPTIMAL_READY` is a non-official architecture designation.

The machine-readable authority is `advanced-maturity-scope.yaml`.
